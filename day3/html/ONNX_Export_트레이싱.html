ONNX Export — 코드가 설계도가 되는 순간

트레이싱: dummy 입력을 흘려보내며 연산을 몰래 기록한다 (torch.onnx.export의 실체)
문제: NPU 컴파일러는 파이썬을 못 읽는다 → 프레임워크 독립 설계도(그래프)가 필요 함정의 뿌리 단 하나: "트레이스 당시 실행된 것만, 그때 값 그대로 박제된다"
함정 체험 — if 분기 모델을:
보는 법 (위: 트레이싱 레코더) — ▶ 버튼을 누르면 dummy 입력이 코드를 통과하며 한 줄 실행될 때마다 오른쪽 장부에 그래프 노드가 하나씩 기록됩니다. 7줄짜리 파이썬 함수가 노드 5개 + initializer 4개짜리 순수 데이터(설계도)로 변신 — 이 설계도가 .onnx 파일이고, if도 for도 없으니 NPU 컴파일러가 읽을 수 있습니다.
보는 법 (아래: 함정 체험) — if 분기가 있는 모델을 양수 dummy로 트레이스하면 ReLU 경로만, 음수 dummy로 트레이스하면 ReLU 없는 경로만 박제되고 반대 경로는 👻 유령이 됩니다. 반대 부호 입력을 넣으면 에러 없이 조용히 틀린 답이 나옵니다 — 교안 "함정 6가지"(dynamic shape 박제, opset 사전, custom layer...)가 전부 이 한 원리의 변주입니다.
수업 연결 — 「ONNX Export 첫걸음」 노트북과 같은 모델(5노드)·같은 함정 실험을 씁니다. 노트북에서는 batch=1로 박제된 Reshape이 batch=4에서 폭발하는 실험(교안 함정 1번)과 onnx-simplifier 원리(8→5노드 청소)까지 직접 코드로 재현합니다.
